# 02 系统架构设计说明书

| 项目 | 内容 |
| --- | --- |
| 文档版本 | V1.0.1 |
| 编制日期 | 2026-10-31 |
| 适用范围 | 智析 ChatBI V1.0 前端、主 API、Agent Runtime、DataLink 与存储 |
| 读者 | 架构、后端、前端、测试、运维 |

## 1 架构目标与原则

架构同时满足两个看似矛盾的目标：**评审现场低门槛可复现**，以及**企业真实分析的受控边界**。

| 原则 | 落地方式 |
| --- | --- |
| 受控优先 | 模型不直接接触数据库；所有数据访问经白名单工具、只读网关、沙箱或 DataLink |
| 证据优先 | 事实来自查询结果；答案与 SQL 审计、Artifact、引用材料绑定，可回放 |
| 双模式运行 | 无 Key / 无数据源时进入演示模式；配置齐全后切换真实 Run |
| 边界清晰 | 浏览器不持有密钥、不直连模型、不直连 DataLink |
| 单进程一致性 | Run、SSE 与取消状态在单 worker 内协作，避免多进程状态分裂 |
| 可替换模型 | 通过 OpenAI-compatible 接口与 ModelProfile 抽象模型供应商 |
| 可观测 | request_id、run_id、事件序号、Trace DAG、可选 LangSmith |

## 2 总体架构

```text
展示层  Vue 3 + TypeScript + Pinia + ECharts + Tailwind CSS
  ChatBIDashboard / WorkspaceView / DatasourcesView / ModelSettingsView
  session / datasource / model / run / artifact
        │ HTTP JSON / SSE
        ▼
API 层  FastAPI（8280，单 worker）
  RequestId / CORS / JSON Envelope / Error Handlers
  sessions / runs / datasources / model-profiles / deepseek
        │
        ▼
运行时  runtime/ + packages/agent_runtime
  RunExecutor / RunLifecycle / RunEventPipeline / RunContextResolver
  LangGraph 状态机 / 工具白名单 / 预算熔断 / Claim 校验 / Trace DAG
        │
        ▼
数据访问  SQL Gateway / Python Sandbox / DataLink Client
  SQLGlot AST / 白名单 / LIMIT / 审计
  Docker 禁网 / 只读 / 限资源
  REST + MCP / 语义图谱
        │
        ▼
持久化  Metadata SQLite（17 张表）/ Artifact / Trace / 工作区
        │
        ├── DataLink 语义服务（8281）：建图 / 版本 / MCP
        └── DeepSeek Responses API：deepseek-flash（stream）
```

## 3 分层职责与边界

| 层 | 主要组件 | 职责 | 明确不做什么 |
| --- | --- | --- | --- |
| 展示层 | 4 个视图、20+ 组件 | 页面、输入、图表、状态呈现 | 不保存 Key、不连接数据库、不直连模型 |
| 状态层 | Pinia stores | Session、DataSource、Model、Run、Artifact 投影 | 不写入密钥；不重复实现后端业务规则 |
| API 层 | FastAPI routes、dependencies | 校验、事务、服务装配、SSE | 不返回上游原始错误体；不绕过应用层 |
| 应用层 | application/*.py | 用例编排、Run 创建、数据源、模型、外部客户端 | 不直接拼 SQL；不持有请求级全局状态 |
| 运行时 | runtime/*、agent_runtime | 阶段状态机、工具调用、预算、校验、事件 | 不越过工具白名单；不直接写业务库 |
| 数据访问 | data_gateway、docker_sandbox、datalink_client | 只读查询、隔离计算、语义检索 | 不写源库；不联网；不读取未授权文件 |
| 持久化 | metadata、storage | Run/Event/Audit/Artifact/Secret | 不保存明文密钥；不保存完整敏感结果到日志 |

## 5 运行模式

| 模式 | 触发条件 | 分析路径 | 数据来源 | 页面标识 |
| --- | --- | --- | --- | --- |
| 演示模式 | 无真实数据源 / 无激活模型 / API 不可用 | 本地确定性回答，或 DeepSeek 聚合上下文 SSE | `data/demo/chatbi_sales_summary.json` | “演示 · 906 条订单” |
| 真实模式 | 数据源 ready + 遮蔽确认 + 模型激活 | 受控 Agent Run | 数据源只读查询 + Artifact | 数据源名称 + Run 状态 |

两种模式都保留明确来源标签，避免用户把演示结果误认为企业事实。演示模式不是“假数据兜底”，而是可独立验收的产品路径。

## 6 链路 A：演示问数

```text
Browser
  └─ POST /ai/deepseek/analyze {question}
       └─ FastAPI（读取服务端 DEEPSEEK_API_KEY）
            ├─ 构造受限聚合上下文（订单数/金额/毛利/区域/产品/月份）
            ├─ AsyncOpenAI Responses API（base_url=api.deepseek.com, stream=true）
            └─ 事件映射
                 response.output_text.delta → SSE event: delta
                 response.completed        → SSE event: done
                 error                     → SSE event: error
  └─ 前端追加 delta，完成显示来源与限制
```

失败策略：401/402 不重试；timeout/connection/429/5xx 仅在未输出文本时退避；已输出文本后不重放。Key 缺失或服务不可用时，前端降级为本地确定性回答。

## 7 链路 B：真实 Run

### 7.1 创建

1. 前端在 `/analysis` 选择 Session 与已 ready 的数据源。
2. `POST /sessions/{id}/runs` 携带问题与幂等键。
3. `RunExecution` 校验会话、幂等键、是否有活跃 Run；解析 `RunContext`，冻结数据源、Schema 版本、模型配置、DataLink 版本、预算与超时。
4. 写入 `runs` 与 `messages`，追加 `run.queued` 事件，调度后台执行，返回 202。

### 7.2 执行阶段

```text
Opening（是否需要数据 / 是否澄清）
   ↓
Preparation（固定 Schema、DataLink 语义上下文、模型能力）
   ↓
Protocol Selected（general-task / ready / discovery / context_only / clarification）
   ↓
Discovery（探索表、字段、行数、关系；最多 2 次尝试）
   ↓
Analysis（LangGraph：agent → execute_tool → require_commit → final_answer）
   ├─ run_sql_readonly  只读查询 + 审计
   ├─ run_python        沙箱计算 + Artifact
   ├─ explore_datalink  语义检索 + 消费记录
   └─ commit_analysis_claims 提交 Claim / Assertion
   ↓
Validation（事实校验、引用校验、产物校验）
   ↓
Final Answer（流式 Markdown + 引用编号 + 证据快照）
```

### 7.3 事件与回放

Run 事件账本同时服务 SSE 与历史回放。事件类型覆盖 25 种，包括 `run.queued`、`run.started`、`run.preparation.started/completed`、`run.protocol.selected`、`analysis.clarification.requested`、`analysis.requirement.blocked`、`analysis.discovery.observed`、`agent.turn.started/completed`、`final_answer.*`、`tool.called/succeeded/failed`、`artifact.created`、`answer.delta/ready`、`run.cancel_requested`、`run.succeeded/failed/canceled`。

前端 `runStore` 将事件投影为 Run 状态、阶段、工具调用、SQL 审计、Artifact 与 DAG；历史 Run 只读回放，不重复调用模型。

### 7.4 取消、超时与恢复

- 取消：`POST /runs/{id}/cancel` 写入取消登记，执行器在下一个检查点终止并落 `run.canceled`。
- 总超时：Run 默认 600 秒上限，执行器用 `asyncio.wait_for` 包裹，超时后取消并落 `run.failed`（`RUN_TIMEOUT`）。
- 恢复：服务启动时 `RunRecoveryService` 扫描非终态 Run，恢复为失败/取消终态；数据源检查、DataLink 构建与校验同样恢复中断状态。

## 8 链路 C：DataLink 语义图谱

```text
数据源 Schema
   └─ DataLink 服务（8281）
        ├─ 建图：表 → 业务实体，字段 → 属性，外键/采样 → 关系与 Join 线索
        ├─ 修订：草稿 → 校验 → 发布版本（revision/version）
        ├─ 检索：MCP 工具按业务词召回实体、属性、关系与字段映射
        └─ 消费：每次 Run 记录 datalink_consumptions，保留版本与命中项
   └─ 主 API 通过 REST/MCP 客户端调用，浏览器不直连
```

价值：自然语言中的“客户”“回款”“区域”往往不是物理字段名。DataLink 把业务词映射到表/字段/关系，减少模型猜字段和错误 Join；版本化保证历史 Run 可复现。

## 9 数据持久化

| 分组 | 表 | 用途 |
| --- | --- | --- |
| 数据资产 | `data_sources`、`connection_grants`、`secrets` | 数据源、连接授权、加密凭据 |
| 模型 | `model_profiles` | 服务商、模型、参数、能力快照 |
| 会话 | `sessions`、`session_preferences`、`conversation_context_states`、`historical_answer_summaries` | 会话、偏好、上下文、历史答案摘要 |
| 消息与 Run | `messages`、`runs` | 问题、答案、Run 上下文与终态 |
| 事件与工具 | `run_events`、`tool_calls` | 事件账本、工具调用摘要 |
| 审计与产物 | `sql_audit_logs`、`artifacts`、`artifact_cleanup_tasks` | SQL 审计、产物、清理任务 |
| DataLink | `datalink_validations`、`run_datalink_consumptions` | 构建校验、Run 语义消费 |

迁移使用 Alembic，当前 31 个版本（`0001`–`0031`），覆盖基础元数据、数据源网关、模型运行时、Run 事件、上下文、DataLink 校验与消费等演进。

## 10 部署拓扑

| 服务 | 端口 | 运行方式 | 对外暴露 |
| --- | --- | --- | --- |
| Web | 5280 | Vite 开发服务 / 静态构建 | 是（评审入口） |
| FastAPI | 8280 | Python 3.12、Uvicorn、单 worker | 是（仅 API） |
| DataLink | 8281 | Python 3.12、Uvicorn | 否（仅内网 / 本机） |
| DeepSeek | HTTPS | 外部 Responses API | 出站 |

Windows 通过批处理启动三项服务；生产环境使用 HTTPS 反向代理，DataLink 仅内网访问，`storage` 与 Metadata 最小权限并定期备份。端口占用时脚本拒绝强杀未知进程。

## 11 可靠性设计

| 场景 | 设计 |
| --- | --- |
| 健康检查 | `/health` 检查 Metadata、数据源根、Artifact 根与 DataLink；DataLink 不可用返回 `degraded` 而非 500 |
| SSE 中断 | 浏览器断开时停止读取并释放 reader；历史事件可重新拉取 |
| 上游异常 | 401/402 不重试；timeout/429/5xx 有限退避；已输出不重放 |
| 服务重启 | 恢复非终态 Run、数据源检查、DataLink 构建与校验 |
| 重复提交 | Run 创建使用幂等键；同一 Session 只允许一个活跃 Run |
| 资源泄漏 | ECharts dispose、ResizeObserver disconnect、timer/SSE reader 释放 |
| 数据库一致性 | 单 worker + 事务写入 + 事件序号；迁移前备份 |

## 12 安全设计

- **凭据**：Key 只从服务端环境变量或 `SecretCipher` 加密 Secret 读取；前端、日志、报告、截图、Git 均不得出现。
- **网络**：浏览器 → FastAPI；FastAPI → DataLink（内网）；FastAPI → DeepSeek（出站）。DataLink 不面向公网。
- **数据库**：只读 SQL；SQLGlot AST 白名单；LIMIT 100/500；60 秒超时；审计每次尝试。
- **脚本**：Docker `--network none`、`--cpus 1`、`--memory 512m`、`--pids-limit 64`、`--cap-drop ALL`、只读根文件系统；30 秒超时。
- **数据**：字段遮蔽显式确认；上下文只发送聚合；日志不记录 Authorization、Key、完整结果。

## 13 可观测性

- 每个 HTTP 请求有 `request_id`；每个 Run 有 `run_id` 与事件 `seq`。
- Trace DAG 由事件推导，展示阶段、工具调用、产物与证据关系。
- 可选 LangSmith：`LANGSMITH_TRACING=true` 时记录 LangChain/LangGraph 原生 Trace。
- 日志允许记录启动时长、阶段、错误类别、端口；禁止记录 Key、Authorization、完整查询结果与模型完整上下文。

## 14 关键架构决策

| 决策 | 选择 | 理由 | 代价 |
| --- | --- | --- | --- |
| 进程模型 | FastAPI 单 worker | Run、SSE、取消依赖进程内状态，避免多进程分裂 | 不能水平扩展 API |
| 事件模型 | 统一事件账本 | SSE 与历史回放共用一份事实，减少双写不一致 | 事件表增长需归档 |
| 数据访问 | 模型只调白名单工具 | 防止自由生成 SQL 越权、写库、失控 | 工具能力需持续打磨 |
| 模型接入 | OpenAI-compatible | 可替换供应商，DeepSeek 直接兼容 SDK | 依赖供应商能力差异 |
| 语义层 | 独立 DataLink 服务 | 语义图谱与主服务解耦，可独立版本化 | 多一个进程与部署面 |
| 元数据 | SQLite + Alembic | 演示部署零依赖、迁移可控 | 高并发与大团队需换库 |
| 演示模式 | 固定 CSV + 汇总 JSON | 评审无 Key 可复现，数据可对账 | 需维护合成数据脚本 |

## 15 风险与演进

| 风险 | 影响 | 缓解 | 演进 |
| --- | --- | --- | --- |
| SQLite 并发 | 多人同时分析时写入竞争 | 单 worker、短事务、事件批量写 | 切换 PostgreSQL |
| 大模型幻觉 | 结论超出数据 | Claim/Assertion 校验、引用、缺字段拒答 | 增加事实覆盖率与回归集 |
| DataLink 建图质量 | 业务词召回不准 | 人工修订、版本发布、消费审计 | 引入指标层与术语表 |
| Docker 依赖 | 真实 Python 产物无法生成 | 演示与 SQL 路径不依赖 Docker | 提供无 Docker 的受限运行时 |
| 成本与延迟 | 复杂问题轮次多 | 预算、上下文裁剪、缓存、deepseek-flash | 分层模型路由 |
| 企业权限 | 单工作空间不满足多租户 | 明确 V1.0 边界 | 引入组织、角色、行级权限 |
