## 1 文档说明

本文档定义智析 ChatBI V1.0 的数据模型、字段字典、HTTP 接口、SSE 事件、错误码与存储约束。接口实现以 `apps/api/server/routes` 为准，契约以 `packages/contracts` 为准；本文档描述二者对外表现，不替代代码中的 Pydantic 校验。

## 2 数据模型总览

| 模型 | `model_profiles` | id、provider、model_name、base_url、temperature、timeout、context_window、reasoning_mode、capability_json、is_active | 模型配置与能力快照 |
| 会话 | `sessions` | id、title、created_at、updated_at、datasource_scope | 会话 |
| 会话 | `session_preferences` | session_id、key、value | 会话偏好 |
| 会话 | `conversation_context_states` | session_id、state_json、version | 结构化上下文 |

### 2.1 Run 状态

| 状态 | 含义 | 终态 |
| --- | --- | --- |
| `queued` | 已创建，等待执行 | 否 |
| `running` | 执行中 | 否 |
| `succeeded` | 成功完成 | 是 |
| `failed` | 失败 | 是 |
| `canceled` | 已取消 | 是 |

`completion_kind` 进一步区分 `completed`、`clarification`、`partial`、`failed`、`canceled`。

### 2.2 数据源状态

| 状态 | 含义 | 可创建 Run |
| --- | --- | --- |
| `uploaded` | 文件已上传 | 否 |
| `checking` | Schema 检查中 | 否 |
| `schema_ready` | Schema 已就绪，待确认遮蔽 | 否 |
| `ready` | 遮蔽已确认，可分析 | 是 |
| `failed` | 检查失败，可重试 | 否 |
| `deleted` | 已删除 | 否 |

## 5 主 API 约定

### 5.1 请求与响应

- 基础地址：`http://127.0.0.1:8280`。
- 请求与响应均为 JSON；文件上传为 `multipart/form-data`。
- 成功响应：

```json
{
  "request_id": "req-...",
  "data": {},
  "error": null
}
```

- 失败响应：

```json
{
  "request_id": "req-...",
  "data": null,
  "error": {
    "code": "DATASOURCE_NOT_READY",
    "message": "数据源尚未就绪",
    "details": {}
  }
}
```

- `request_id` 由 `RequestIdMiddleware` 注入，响应头同时返回，便于日志关联。
- 分页接口使用 `page`、`page_size`，返回 `items`、`total`、`page`、`page_size`。

### 5.2 健康检查

`GET /health`

```json
{
  "status": "healthy",
  "metadata": "ok",
  "datasource_root": "ok",
  "artifact_root": "ok",
  "datalink": "ok"
}
```

DataLink 不可用时 `status=degraded`、`datalink=unavailable`，不返回 500。

## 7 Run 事件契约

事件类型共 25 种，SSE 与历史回放共用同一 DTO：

```json
{
  "run_id": "run-...",
  "seq": 12,
  "type": "tool.succeeded",
  "timestamp": "2026-10-29T09:42:11Z",
  "payload": { "tool_name": "run_sql_readonly", "row_count": 5 }
}
```

| 分组 | 事件 |
| --- | --- |
| 生命周期 | `run.queued`、`run.started`、`run.preparation.started`、`run.preparation.completed`、`run.protocol.selected` |
| 需求与澄清 | `analysis.clarification.requested`、`analysis.requirement.blocked`、`analysis.discovery.observed` |
| Agent | `agent.turn.started`、`agent.turn.completed` |
| 最终答案 | `final_answer.request.started`、`final_answer.response.received`、`final_answer.validation.failed`、`final_answer.request.timed_out`、`final_answer.truncated` |
| 工具 | `tool.called`、`tool.succeeded`、`tool.failed` |
| 产物与答案 | `artifact.created`、`answer.delta`、`answer.ready` |
| 终态 | `run.cancel_requested`、`run.succeeded`、`run.failed`、`run.canceled` |

约束：

- `payload` 只能是安全摘要，最多 40 个键；不得包含 Key、Authorization、完整查询结果、完整模型上下文。
- `seq` 在 Run 内单调递增，用于断线重连与去重。
- SSE 格式为 `event: <type>`、`data: <json>`、空行；需关闭代理缓冲。

## 8 SSE 协议

### 8.1 DeepSeek 演示问数

| 事件 | data | 前端行为 |
| --- | --- | --- |
| `status` | `{ "state": "analyzing" }` | 进入分析态，禁用发送 |
| `delta` | `{ "text": "..." }` | 追加文本 |
| `error` | `{ "code": "...", "message": "..." }` | 展示稳定提示，必要时降级 |
| `done` | `{ "elapsed_ms": 1234 }` | 结束 loading，显示来源 |

### 8.2 Run 事件

前端 `runStore` 按 `seq` 排序、去重、投影。断线后先拉取 `/events/history` 补齐，再重新订阅 `/events`。历史 Run 只读回放，不重复调用模型。

## 9 通用状态码

| 状态 | 含义 | 典型场景 |
| --- | --- | --- |
| 200 | 成功 | 查询、详情、SSE 建立 |
| 201 | 已创建 | 新建 Session / ModelProfile |
| 202 | 已接受 | 上传数据源、创建 Run |
| 400 | 请求格式错误 | JSON 缺字段、问题超长 |
| 401 | 未授权 | DeepSeek Key 无效 |
| 402 | 余额不足 | DeepSeek 账户余额不足 |
| 404 | 不存在 | Session / Run / Artifact 不存在 |
| 409 | 状态冲突 | 数据源未就绪、遮蔽未确认、已有活跃 Run |
| 422 | 校验失败 | Pydantic 字段不合法 |
| 429 | 限流 | 上游 429 |
| 500 | 内部错误 | 未预期异常（已脱敏） |

错误码示例：`RUN_NOT_FOUND`、`RUN_ALREADY_ACTIVE`、`RUN_ALREADY_FINISHED`、`RUN_TIMEOUT`、`DATASOURCE_NOT_READY`、`MASK_NOT_CONFIRMED`、`MODEL_NOT_ACTIVE`、`WRITE_STATEMENT`、`INVALID_LIMIT`。

## 11 迁移与版本

Alembic 当前 31 个版本（`0001`–`0031`），覆盖：

- `0001`–`0005`：基础元数据、数据源网关、模型运行时、Run 事件；
- `0006`–`0018`：核心运行时重构、能力快照、答案分区、证据引用、上下文；
- `0019`–`0031`：协议路由、结构化上下文、DataLink 校验/消费、连接数据源、证据快照、推理模式。

升级命令：`.venv\Scripts\python.exe -m alembic upgrade head`。升级前备份 Metadata 与 Artifact。

## 12 安全约束

- Key 不进入请求体、响应体、日志、报告；ModelProfile 详情只返回 `has_api_key`。
- SQL 只读，结果限流，审计完整；拒绝原因不泄露内部路径。
- 字段遮蔽确认前不创建 Run；遮蔽字段不进入 Schema 投影、SQL、上下文与报告。
- 演示数据为合成数据；页面与报告标注来源。
