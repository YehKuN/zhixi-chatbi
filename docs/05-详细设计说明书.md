## 1 设计范围

本文档描述智析 ChatBI V1.0 的模块级实现：前端路由与状态、API 装配、Run 创建与执行、Agent 状态机、SQL 网关、Python 沙箱、DataLink 客户端、持久化与资源管理。需求编号见 01，架构见 02，接口字段见 06，AI 方案见 07。

## 2 前端详细设计

### 2.1 路由与视图

| 路由 | 视图 | 关键职责 |
| --- | --- | --- |
| `/` | 重定向 | 转到 `/workspace` |
| `/workspace` | `ChatBIDashboard.vue` | 驾驶舱、问数、报告、台账、收支 |
| `/analysis` | `WorkspaceView.vue` | Session / Run、事件、证据、产物 |
| `/datasources` | `DatasourcesView.vue` | 数据源、Schema、遮蔽、DataLink |
| `/settings/model` | `ModelSettingsView.vue` | 模型配置、测试、激活 |

`App.vue` 提供应用壳、全局导航、主题与健康状态；`router.ts` 使用 `createWebHistory`，生产部署需服务端 history fallback。

### 2.2 状态管理

| Store | 状态 | 主要动作 |
| --- | --- | --- |
| `sessionStore` | 会话列表、当前会话、消息 | 加载、创建、选择、追加消息 |
| `datasourceStore` | 数据源、Schema、遮蔽 | 上传、连接、检查、确认遮蔽 |
| `modelStore` | 模型配置、激活项 | 创建、测试、激活、删除 |
| `runStore` | 当前 Run、事件、投影、工具、审计、产物、DAG、SSE 状态 | 创建、订阅、取消、回放 |
| `artifactStore` | 产物预览与下载 | 加载、缓存、释放 |

`runProjection.ts` 把事件流投影为可渲染状态：阶段、工具调用、SQL 审计、Artifact、证据、终态。实时与回放使用同一投影，避免两套逻辑。

### 2.3 驾驶舱状态

`ChatBIDashboard.vue` 使用：

- `activeSection`：`dashboard / query / reports / ledger / finance`；
- `isAnalyzing`：控制发送按钮与分析动画；
- `latestQuestion`、`aiConclusion`、`analysisSource`：当前答案；
- `insightItems`、`metrics`、`channelLegend`、`regionRows`：由 `demoSummary` 派生；
- `trendChart`、`channelChart`、`regionChart`：ECharts 实例，挂载初始化、卸载 dispose；
- `ResizeObserver`：容器尺寸变化时 resize；卸载时 disconnect；
- `toastTimer`：卸载时清理。

演示指标、趋势、渠道、区域、回款与交易明细全部读取 `demoSummary.json`，组件不得另存固定业务数值。

### 2.4 问数状态转换

| 当前状态 | 事件 | 下一状态 | 动作 |
| --- | --- | --- | --- |
| ready | 提交非空问题 | analyzing | 记录问题、禁用发送 |
| analyzing | 真实 ChatBI 就绪 | run_active | 创建 Session/Run 并订阅事件 |
| analyzing | 演示模式 | stream_active | 调用 DeepSeek SSE |
| stream_active | delta | stream_active | 追加文本 |
| stream_active | done | success | 清除 loading、显示来源 |
| stream_active | error | fallback | 分类提示并生成演示回答 |
| run_active | Run succeeded | success | 读取答案、产物与引用 |
| run_active | Run failed/canceled | error | 展示安全错误状态 |

输入规则：1–2000 字符；Enter 提交，Shift+Enter 换行；空值、纯空白、超长阻止；分析中禁用发送；推荐问题填充并聚焦；新问题不覆盖未完成的上一条回答。

### 2.5 图表与格式化

- 金额以元存储，页面用 `formatWan` 转为万元显示；tooltip 含单位与时间范围。
- 月度趋势使用自然月；本月同期使用相同截止日；毛利率 = 毛利 / 订单金额。
- 图表容器使用 `role="img"` 与 `aria-label`；颜色之外同时使用文字与图标。
- 卸载时释放 ECharts、ResizeObserver、timer 与 SSE reader。

### 2.6 错误与降级

- API 错误统一转换成稳定中文提示，不展示堆栈与上游原始响应。
- DeepSeek 不可用、Key 缺失、API 不可用时进入演示模式，保留驾驶舱、问数、报告导出。
- 真实 Run 失败不覆盖历史成功结果；历史 Run 只读回放。

## 3 API 层详细设计

### 3.1 应用装配

`apps/api/server/app.py` 的 `create_app(settings, datalink_client)`：

1. 读取 `Settings`，应用 LangSmith 环境变量，确保存储目录存在。
2. 创建 SQLite 引擎与 Session 工厂。
3. 装配 `RunEventNotifier`、`RunCancelRegistry`、`ValidationCancelRegistry`。
4. 装配 `RunExecutor`、`RunRuntimeService`、`RunLifecycleCoordinator`。
5. 注册 `RequestIdMiddleware`、CORS、异常处理器与路由。
6. lifespan 启动时恢复中断的 Run、数据源检查、DataLink 构建与校验；关闭时 dispose 引擎。

### 3.2 中间件与错误信封

- `RequestIdMiddleware` 为每个请求注入 `request_id`，写入响应头与日志。
- 成功响应 `{request_id, data, error: null}`；失败响应 `{request_id, data: null, error: {code, message, details}}`。
- `AppError` 映射业务错误；`RequestValidationError` 映射 422；未预期异常映射 500 并脱敏。
- 不返回上游原始错误体、Key、Authorization、完整 SQL 结果。

### 3.3 路由职责

| 路由 | 职责 |
| --- | --- |
| `sessions.py` | 会话、消息、创建 Run、Run 列表 |
| `runs.py` | Run 详情、取消、SSE、历史事件、工具、DAG、审计、产物 |
| `datasources.py` | 类型、上传、连接、Schema、遮蔽、重检、删除、DataLink |
| `model_profiles.py` | 列表、创建、详情、更新、测试、激活、删除 |
| `deepseek.py` | 演示问数 SSE |

## 4 Run 创建与执行

### 4.1 创建

`RunExecution`：

1. 校验 Session 存在、问题长度、幂等键。
2. 检查是否已有活跃 Run；有则返回 409 `RUN_ALREADY_ACTIVE`。
3. 解析 `RunContext`：数据源、Schema 版本、模型配置、DataLink 版本、预算、超时。
4. 写入 `runs` 与 `messages`，追加 `run.queued` 事件。
5. 调度后台执行，返回 202。

### 4.2 执行

`RunExecutor`：

- 用 `asyncio.wait_for` 包裹 `runtime.execute`，总超时默认 600 秒。
- 超时后触发取消，落 `RUN_TIMEOUT` 失败终态。
- 异常按类别落 `run.failed`，保留可读原因。
- 取消登记在检查点生效，落 `run.canceled`。

`RunRuntimeService`：

- 装配 Agent Runtime、SQL Gateway、Sandbox、DataLink 客户端。
- 执行阶段推进，发布事件，登记工具调用、SQL 审计、产物与 DataLink 消费。
- 最终答案保存证据快照。

### 4.3 事件与回放

- `RunEventPipeline` 负责事件发布、持久化与通知。
- SSE 与历史接口共用 `RunEventRead` DTO。
- `RunRecoveryService` 启动时扫描非终态 Run，恢复为失败/取消终态。
- 历史 Run 只读回放，不调用模型。

### 4.4 超时与预算

| 配置 | 默认值 |
| --- | --- |
| Run 总超时 | 600 秒 |
| Preparation | 240 秒 |
| Opening | 60 秒 |
| Semantic Context | 30 秒 |
| Plan Followup | 120 秒 |
| Commit | 120 秒 |
| Agent Turn | 120 秒 |
| Final Answer | 45 秒 |
| Final Answer Idle | 30 秒 |
| Python Sandbox | 30 秒 |

预算：20 回合、16 次数据工具调用、2 次阶段失败、2 次 Claim 校验失败、2 次沙箱拒绝、2 次 SQL 修复、2 次 Discovery、32 条消息、64000 字符、8 个断言、每断言 3 次查询。

## 5 Agent Runtime 详细设计

### 5.1 状态机

LangGraph 节点：`agent → execute_tool → require_commit → final_answer`。

| 节点 | 输入 | 输出 |
| --- | --- | --- |
| `agent` | 工作集、计划、观察 | 工具调用或提交意图 |
| `execute_tool` | 工具名、参数 | 观察、审计、事件 |
| `require_commit` | 观察、断言 | Claim 提交或校验失败 |
| `final_answer` | Claim、材料 | Markdown 答案、引用、快照 |

### 5.2 合同与校验

- `AnalysisRequirement`、`AnalysisPlan`、`AnalysisAssertion`、`AnalysisQueryAttempt`、`AnalysisClaim` 使用 Pydantic 合同。
- `analysis_planning.py` 校验计划与 Schema 一致、断言字段存在、物理引用合法。
- `fact_validator.py` 比对 Claim 与查询结果。
- `result_verifier.py` 校验行数、列名、数值与引用。
- `answer_materials.py` 组织材料与图表规格。
- `answer_citations.py` 解析并校验引用编号。
- 失败按预算重试或收尾为部分完成。

### 5.3 工具

| 工具 | 入口 | 说明 |
| --- | --- | --- |
| `run_sql_readonly` | SQL Gateway | 只读查询、审计 |
| `run_python` | Docker Sandbox | 计算与产物 |
| `explore_datalink` | DataLink Client | 语义检索 |
| `commit_analysis_claims` | Runtime | 结构化结论 |

## 6 SQL 只读网关

`packages/data_gateway/sql_guard.py`：

1. SQLGlot 解析 AST。
2. 必须是 `Query`；拒绝 `INTO`、`INSERT`、`UPDATE`、`DELETE`、`CREATE`、`DROP`。
3. 表白名单与字段白名单校验（来自 Schema 与遮蔽）。
4. LIMIT：缺省注入 100；显式必须是整数且 ≤ 500。
5. 单次查询超时 60 秒。
6. 写入 `sql_audit_logs`：原始 SQL、规范化 SQL、状态、拒绝码、行数、耗时。

拒绝码：`WRITE_STATEMENT`、`INVALID_LIMIT`、`TABLE_NOT_ALLOWED`、`COLUMN_NOT_ALLOWED`、`QUERY_TIMEOUT`。拒绝原因返回给 Agent 用于修复，不泄露内部路径与凭据。

## 7 Python Sandbox

`apps/api/application/docker_sandbox.py`：

- 固定入口 `python analysis.py`。
- Docker 参数：`--network none`、`--cpus 1`、`--memory 512m`、`--pids-limit 64`、`--cap-drop ALL`、只读根文件系统。
- 脚本与输入只读挂载；输出目录受控。
- 30 秒超时；stdout/stderr 截断后返回。
- 产物登记 Artifact，记录 MIME、大小与预览。

## 8 DataLink 客户端

`apps/api/application/datalink_client.py`：

- 通过 `DATALINK_BASE_URL` 访问 REST，通过 `DATALINK_MCP_URL` 访问 MCP。
- 超时 `DATALINK_TIMEOUT_SECONDS`，默认 180 秒。
- 建图、修订、校验、发布、检索由 DataLink 服务实现；主 API 只编排与记录消费。
- DataLink 不可用时降级为 Schema 浏览。

## 9 持久化与仓储

- `packages/metadata/models.py` 定义 17 张表；`repositories.py` 提供仓储。
- 迁移由 Alembic 管理，当前 31 个版本。
- Run、事件、工具、审计、产物、DataLink 消费均以 Run 为中心关联。
- 事务边界在应用层；事件写入与通知顺序保证 SSE 与历史一致。

## 10 配置与密钥

- `Settings` 从环境变量读取，启动时校验范围。
- `SecretCipher` 使用 `SECRET_MASTER_KEY` 加密模型凭据；详情只返回 `has_api_key`。
- Key 不进入前端 bundle、localStorage、日志、报告、截图。
- LangSmith 通过 `LANGSMITH_TRACING` 可选开启。

## 11 并发、资源与异常

| 场景 | 设计 |
| --- | --- |
| 重复提交 | 幂等键 + 单活跃 Run |
| SSE 断开 | 停止读取、释放 reader；历史事件补齐 |
| 服务重启 | 恢复非终态 Run、数据源检查、DataLink 构建与校验 |
| 图表泄漏 | ECharts dispose、ResizeObserver disconnect |
| 定时器 | 卸载清理 |
| 上游异常 | 401/402 不重试；timeout/429/5xx 有限退避；已输出不重放 |
| 数据库锁 | 单 worker、短事务、事件批量写 |
