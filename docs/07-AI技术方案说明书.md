## 1 技术目标与边界

系统把自然语言理解、企业数据访问、语义映射、受控执行、证据链和可视化组成一个可验证闭环。

**模型负责理解与表达，运行时决定能用什么工具、读什么数据、给出什么证据。** 这条边界是整套 AI 方案的前提：不让大模型自由生成并执行 SQL，不让模型直接接触数据库连接，不让没有来源的数字进入结论。

边界：

- 模型不写业务库，不执行 DDL/DML，不访问系统表。
- 模型不直接读取完整 CSV 或客户明细；上下文只发送最小必要聚合。
- 模型不决定权限、遮蔽与数据源可用性；这些由服务端状态机约束。
- 模型不替用户做财务或人事决策；输出是分析建议，不是执行指令。

## 2 模型选型

### 2.1 选型结论

主分析模型选择 **DeepSeek `deepseek-flash`**，通过 OpenAI Python SDK 的 **Responses API** 接入，`base_url=https://api.deepseek.com`，`stream=true`。

### 2.2 选型维度

| 维度 | 要求 | DeepSeek flash 的匹配度 |
| --- | --- | --- |
| 中文理解 | 能理解“回款”“毛利率”“同期”“区域占比”等业务表达 | 中文语料充分，业务词理解稳定 |
| 工具调用 | 能按 JSON Schema 调用 4 个白名单工具 | 支持 function/tool calling，结构化参数 |
| 流式输出 | 首片延迟低，能逐片渲染 | Responses API 支持 `output_text.delta` |
| 接口兼容 | 能复用 OpenAI SDK、便于替换供应商 | OpenAI-compatible，切换成本低 |
| 成本 | 演示与多次回归可承受 | flash 档位单价低，适合高频分析 |
| 推理能力 | 多步计划、SQL 修复、结论归纳 | 支持推理模式，复杂问题可分阶段推进 |
| 可观测 | 能记录 token、耗时、失败类别 | SDK 返回 usage 与事件状态 |

### 2.3 备选方案与取舍

| 方案 | 优势 | 未选择的原因 |
| --- | --- | --- |
| GPT-4o / 4o-mini | 生态成熟、工具调用稳定 | 成本与网络可达性对评审环境不友好 |
| Qwen 系列 | 中文强、国内可达 | 需要额外适配；本项目优先统一 OpenAI-compatible 抽象 |
| 本地 Ollama | 完全离线、隐私最好 | 本机算力与上下文窗口不足，复杂多步分析稳定性弱 |
| 纯规则 / 模板 | 可控、零成本 | 无法处理开放问法，失去“对话式分析”的产品价值 |

> 说明：本项目的模型选择基于能力、成本、中文与接口兼容性做工程判断，不以“某模型全面优于某模型”作为结论。模型可通过 ModelProfile 替换，选型不是硬编码。

### 2.4 双模型角色

| 场景 | 模型 | 说明 |
| --- | --- | --- |
| 主分析 Agent | `deepseek-flash` | 计划、工具选择、SQL 修复、结论组织 |
| DataLink 建图 | `DATALINK_LLM_MODEL`（OpenAI-compatible） | 从 Schema 生成实体/属性/关系草稿；可独立配置 |
| 演示问数 | `deepseek-flash` | 只发送聚合上下文，流式回答 |
| 无模型降级 | 本地确定性规则 | 保证评审无 Key 也能完成主流程 |

## 3 集成方式

### 3.1 服务端持有密钥

```text
Browser ──POST /ai/deepseek/analyze──▶ FastAPI
                                      ├─ 读取 DEEPSEEK_API_KEY（环境变量）
                                      ├─ AsyncOpenAI(base_url, api_key)
                                      └─ Responses API(stream=true)
Browser ◀──SSE: status / delta / error / done── FastAPI
```

- 浏览器请求体只有 `question`，不接受 Key、Base URL、模型名等敏感参数。
- Key 不进入前端 bundle、localStorage、日志、报告、截图。
- 模型请求由主 API 发起，浏览器不直连模型服务，避免 CORS 与密钥暴露。

### 3.2 流式事件映射

| 上游事件 | 下游 SSE | 前端行为 |
| --- | --- | --- |
| 请求开始 | `status` | 进入 analyzing，禁用发送 |
| `response.output_text.delta` | `delta` | 追加文本片段，只追加一次 |
| `response.completed` | `done` | 清除 loading，显示来源与限制 |
| `failed` / 异常 | `error` | 展示稳定错误消息，必要时降级 |
| `incomplete` / 截断 | `error` 或截断标记 | 提示答案不完整，不伪装成功 |

### 3.3 错误分类与重试

| 类别 | 触发 | 策略 | 用户提示 |
| --- | --- | --- | --- |
| `invalid_api_key` | 401 | 不重试 | API Key 无效，请检查服务端配置 |
| `insufficient_balance` | 402 | 不重试 | 账户余额不足 |
| `timeout` | 请求超时 | 未输出文本时有限退避 | 请求超时，正在重试 |
| `connection` | 连接失败 | 未输出文本时有限退避 | 网络连接异常 |
| `upstream_retryable` | 429 / 5xx | 指数退避，最多 2 次 | 服务暂时不可用 |
| `stream_interrupted` | 已输出后中断 | 不重放 | 回答中断，请重试或缩小问题 |

重试的核心约束：**已经向用户输出片段后不重放同一答案**，否则会出现重复内容或前后矛盾。

### 3.4 演示上下文的构造

演示问数不发送完整 CSV。服务端只构造：

- 期间与截止日；
- 订单数、客户数、营收、成本、毛利、毛利率；
- 待回款笔数与金额；
- 区域、渠道、产品、月份的聚合；
- 最近交易的必要字段（脱敏后的演示企业名）。

模型回答必须限定在该上下文内；上下文没有的字段（如转化率、合同条款）应明确说明“数据不足”。

## 4 受控 Agent Runtime

### 4.1 状态机

Agent Runtime 基于 LangGraph 构建，节点为：

```text
agent ──▶ execute_tool ──▶ require_commit ──▶ final_answer
  ▲            │                  │
  └────────────┴──────────────────┘
```

| 节点 | 职责 |
| --- | --- |
| `agent` | 读取工作集，决定下一步工具或提交结论 |
| `execute_tool` | 执行白名单工具，写入观察与审计 |
| `require_commit` | 强制在最终答案前提交结构化 Claim |
| `final_answer` | 生成 Markdown 答案，附引用与限制 |

外层阶段：

```text
Opening → Preparation → Protocol Selected → Discovery → Analysis → Commit → Final Answer
```

- **Opening**：判断是否需要当前数据、是否需要澄清、是否走通用任务。
- **Preparation**：固定 Schema、DataLink 语义上下文、模型能力与预算。
- **Protocol**：在 `general-task / ready / discovery / context_only / clarification` 中选择。
- **Discovery**：探索表、字段、行数与关系；初次查询 + 一次修复。
- **Analysis**：多轮工具调用与观察。
- **Commit**：提交 Claim / Assertion，进入事实校验。
- **Final Answer**：流式输出答案，保存证据快照。

### 4.2 工具白名单

| 工具 | 作用 | 关键约束 |
| --- | --- | --- |
| `run_sql_readonly` | 只读查询 | AST 校验、字段白名单、LIMIT、超时、审计 |
| `run_python` | 计算与产物生成 | Docker 隔离、禁网、限资源、固定入口 `python analysis.py` |
| `explore_datalink` | 语义检索 | MCP、版本化、消费记录、只返回授权范围 |
| `commit_analysis_claims` | 提交结构化结论 | Claim/Assertion 合同、事实校验、引用绑定 |

除这四个工具外，模型不能调用文件系统、网络、Shell 或任意代码执行。

### 4.3 预算与熔断

| 配置 | 默认值 | 作用 |
| --- | --- | --- |
| `AGENT_MAX_TURNS` | 20 | 单 Run 最大 Agent 回合 |
| `AGENT_MAX_DATA_TOOL_CALLS` | 16 | SQL / Python / DataLink 数据工具总调用 |
| `AGENT_MAX_STAGE_TOOL_FAILURES` | 2 | 同阶段连续失败后收尾 |
| `AGENT_MAX_COMMIT_VALIDATION_FAILURES` | 2 | Claim 校验失败重试上限 |
| `AGENT_MAX_SANDBOX_REJECTIONS` | 2 | 沙箱安全拒绝上限 |
| `AGENT_MAX_SQL_REPAIRS` | 2 | SQL 被拒后的改写次数 |
| `AGENT_MAX_DISCOVERY_ATTEMPTS` | 2 | Discovery 初次 + 一次修复 |
| `AGENT_MAX_MODEL_MESSAGES` | 32 | 工作集消息上限 |
| `AGENT_MAX_MODEL_CONTEXT_CHARS` | 64000 | 工作集字符预算 |
| `AGENT_MAX_TOOL_MESSAGE_CHARS` | 32000 | 单条工具观察截断 |
| `AGENT_MAX_COMPACTION_STEPS` | 256 | 上下文压缩最大步骤 |
| `AGENT_MAX_ASSERTIONS_PER_REQUIREMENT` | 4 | 单目标检查项上限 |
| `AGENT_MAX_TOTAL_ASSERTIONS` | 8 | 单 Run 检查项总数 |
| `AGENT_MAX_QUERY_ATTEMPTS_PER_ASSERTION` | 3 | 单检查项查询尝试 |
| `AGENT_MAX_ASSERTION_FAILURES` | 2 | 同类合同错误熔断 |

熔断的意义：把“模型无限重试”变成“有界失败”。当工具连续失败、SQL 反复被拒、Claim 反复校验不过时，Run 进入部分完成或失败终态，并给出可读原因，而不是耗尽时间与费用。

### 4.4 上下文与输出预算

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `AGENT_MODEL_MAX_OUTPUT_TOKENS` | 16384 | 单次模型输出上限，思考 token 与答案共享 |
| `MODEL_CONTEXT_WINDOW_TOKENS` | 45056 | 未在 ModelProfile 指定时的上下文窗口 |
| `ANALYSIS_PREPARATION_MAX_SECONDS` | 240 | 准备阶段共享窗口 |
| `RUN_OPENING_TIMEOUT_SECONDS` | 60 | Opening 模型调用 |
| `ANALYSIS_SEMANTIC_CONTEXT_TIMEOUT_SECONDS` | 30 | DataLink 语义上下文 |
| `ANALYSIS_PLAN_FOLLOWUP_TIMEOUT_SECONDS` | 120 | 计划定稿 |
| `ANALYSIS_FINAL_RESERVE_SECONDS` | 45 | 为 Claim 与最终答案保留 |
| `ANALYSIS_COMMIT_TIMEOUT_SECONDS` | 120 | Claim 提交 |
| `ANALYSIS_AGENT_TURN_TIMEOUT_SECONDS` | 120 | 普通分析单轮 |
| `FINAL_ANSWER_TIMEOUT_SECONDS` | 45 | 最终答案 |
| `FINAL_ANSWER_IDLE_TIMEOUT_SECONDS` | 30 | 流式分片最大空闲 |
| `PYTHON_SANDBOX_TIMEOUT_SECONDS` | 30 | 单次脚本 |
| Run 总超时 | 600 | 上限，执行器统一包裹 |

输入预算按 `窗口 - 输出 - 6144` 计算，避免思考型模型把答案在表格中间截断。

## 5 可信分析机制

### 5.1 从计划到断言

1. **AnalysisRequirement**：把用户目标拆成可验证的需求项。
2. **AnalysisPlan**：声明目标、完成条件、最小字段范围与数据工具。
3. **AnalysisAssertion**：把需求转成结构化检查项（字段、选择器、期望事实）。
4. **AnalysisQueryAttempt**：记录每次查询、结果、状态与关联检查项。
5. **AnalysisClaim**：模型在最终答案前提交结构化事实。
6. **Validation**：事实校验器比对 Claim 与查询结果；结果校验器检查行数、列名、数值与引用。
7. **Answer Materials**：将查询结果、Artifact、DataLink 命中组织成可引用材料。
8. **Evidence Snapshot**：答案落库时保存当时的证据状态，后续回放不漂移。

### 5.2 校验规则

| 规则 | 说明 |
| --- | --- |
| 数字必须来自查询 | 上下文中不存在的数字不得作为事实 |
| 口径必须可解释 | 毛利率 = 毛利 / 订单金额；待回款只统计对应状态 |
| 同期必须对齐 | 10 月 1–29 日对比 9 月 1–29 日 |
| 缺字段必须拒答 | 无漏斗字段不算转化率；无成本字段不算毛利率 |
| 引用必须存在 | 答案中的 `[n]` 必须对应材料编号；未引用材料不进入结论 |
| 产物必须可定位 | Artifact 有 ID、类型、路径与来源 Run |
| 部分完成必须标注 | 未满足全部断言时输出“部分完成”与缺口 |

### 5.3 答案与证据呈现

- Markdown 正文使用 `[1] [2]` 引用编号；前端 `answerCitations` 解析编号并校验范围。
- `AnswerMaterialViewer` 展示材料来源、查询审计、结果表格与下载入口。
- `evidenceResolver` 将引用解析到 Run 事件、SQL 审计、Artifact 或 DataLink 消费。
- `incompleteHint` 在答案不完整时提示缺失项，而不是把部分结果伪装成完整结论。

## 6 数据访问安全

### 6.1 SQL 只读网关

```text
原始 SQL
  ├─ SQLGlot 解析 AST
  ├─ 必须是 Query；拒绝 INTO / INSERT / UPDATE / DELETE / CREATE / DROP
  ├─ 表白名单 + 字段白名单（Schema 与遮蔽）
  ├─ LIMIT：缺省 100；显式必须是整数且 ≤ 500
  ├─ 单次超时 60s
  └─ 写入 sql_audit_logs：原始/规范化 SQL、状态、拒绝码、行数、耗时
```

拒绝码示例：`WRITE_STATEMENT`、`INVALID_LIMIT`、`TABLE_NOT_ALLOWED`、`COLUMN_NOT_ALLOWED`、`QUERY_TIMEOUT`。拒绝原因返回给 Agent 用于修复，但不泄露内部路径与凭据。

### 6.2 Python 沙箱

| 维度 | 配置 |
| --- | --- |
| 网络 | `--network none` |
| CPU | `--cpus 1` |
| 内存 | `--memory 512m` |
| 进程 | `--pids-limit 64` |
| 能力 | `--cap-drop ALL` |
| 文件系统 | `--read-only`，脚本与输入只读挂载 |
| 入口 | 固定 `python analysis.py` |
| 超时 | 30 秒 |

产物写入受控输出目录，登记为 Artifact；脚本不能访问宿主文件系统、网络或其他 Run 的数据。

### 6.3 字段遮蔽

- 数据源接入时生成敏感字段建议清单。
- 用户必须显式确认 `mask_fields` 与 `mask_fields_confirmed`。
- 未确认时创建 Run 返回 409；确认后，遮蔽字段不进入 Schema 投影、SQL 白名单、模型上下文与报告。

## 7 DataLink 语义图谱

### 7.1 建图

1. 读取 Schema：表、字段、类型、主键、外键、行数、样例。
2. 模型生成实体、属性、关系与 Join 线索草稿。
3. 人工修订：合并同义实体、修正字段映射、确认关系。
4. 校验：结构、引用完整性、字段存在性。
5. 发布版本：每次发布形成不可变 revision，Run 创建时冻结版本。

### 7.2 MCP 检索

DataLink 通过 MCP 暴露语义检索能力，Agent 用 `explore_datalink` 按业务词查询：

- “回款” → `payment_status` 字段与取值；
- “区域” → `region` 字段与枚举；
- “客户” → `customers` 实体与主键；
- “订单明细” → 订单与明细的 Join 路径。

返回结果包含实体、属性、物理字段、关系、置信度与版本；每次调用写入 `run_datalink_consumptions`，保证可追溯。

### 7.3 价值

- 降低模型猜字段、猜表名、猜 Join 的概率。
- 把业务术语与物理模型解耦，便于换库与重构。
- 版本化保证历史 Run 可复现，不因语义地图变更而漂移。

## 8 优化策略

### 8.1 上下文优化

| 策略 | 做法 | 效果 |
| --- | --- | --- |
| 最小 Schema 投影 | 只发送当前任务相关表/字段，隐藏遮蔽字段 | 降低 token 与误选 |
| 工作集裁剪 | 只保留最近消息、计划、关键观察与结论 | 控制消息数 ≤ 32 |
| 单条观察截断 | 工具结果超过 32000 字符截断并标注 | 防止单条结果撑爆上下文 |
| 压缩循环 | 超预算时按步骤压缩历史 | 保留事实，丢弃冗余 |
| 语义上下文限时 | DataLink 阶段 30 秒 | 避免建图慢拖垮 Run |
| 输出预算分离 | 输出 16384，输入按窗口减输出与 6144 预留 | 防止答案被截断 |

### 8.2 工具与执行优化

| 策略 | 做法 | 效果 |
| --- | --- | --- |
| SQL 先探索后分析 | Discovery 限制 2 次；先看表/字段/行数 | 减少盲目查询 |
| SQL 修复有界 | 最多 2 次改写 | 防止无限试错 |
| 默认 LIMIT 100 | 结果足够分析，避免全表 | 降低延迟与传输 |
| 沙箱按需 | 只有需要计算/图表产物时才调用 Python | 降低 Docker 依赖与耗时 |
| 流式优先 | 首片即渲染，空闲 30 秒超时 | 体感更快，异常可感知 |
| 事件驱动 UI | SSE 增量投影，不轮询 | 降低请求与延迟 |

### 8.3 成本优化

- 使用 `deepseek-flash` 而非更大模型，复杂问题通过分阶段计划而非单次长上下文解决。
- 只发送聚合摘要，不发送完整 CSV 与客户明细。
- 工具调用、回合数、输出 token、Run 总时长均有上限。
- DataLink 语义结果按版本缓存（`datalink_cache`），同一 Run 内不重复建图。
- 可选 LangSmith 仅在需要时开启，避免额外 trace 成本。

### 8.4 提示与协议优化

| 手段 | 说明 |
| --- | --- |
| 结构化合同 | 计划、断言、Claim 均用 Pydantic/JSON Schema 约束，减少自由文本歧义 |
| 协议路由 | 先判断 `general-task / ready / discovery / context_only / clarification`，避免所有问题都走重分析 |
| Prompt A/B | `scripts/prompt_ab_experiment.py` 对比不同提示词变体的解释准确率与耗时 |
| 回归基准 | 20 题中文电商基准 + 178 条路由用例，改动提示或工具后重跑 |
| 答案数字审计 | `scripts/audit_answer_numbers.py` 检查答案数字与查询结果的一致性 |

- 题库：`data/benchmark/ecommerce-cn`，20 题，覆盖计数、分组、金额、时间、排名、对比、占比。
- 唯一权威：`expected-answers.json`（gold SQL + 列 + 行）。
- 评分：0.05% 相对容差 + gold 小数位舍入 + 字符串/月份同义匹配 + 单元格匹配。
- 结构校验：`score_benchmark.py --lint` 检查题号一致、gold 非空、行数与列数一致、题面 gold 与评分 gold 同源。
- 维护约定：题面是唯一真相；题面与 gold 冲突时修 gold，不改题面；语义核查记录在 `NOTES.md`。

### 9.3 协议路由评测

- 语料：`tests/fixtures/run_protocol_routing.jsonl`，178 条。
- 类别：问候、概念、当前数据、Schema、Discovery、混合、隐式、数据词概念、澄清、约束、对抗，共 11 类。
- 指标：模式准确率、终态类型、资源类型、失败原因分布。
- 脚本：`scripts/evaluate_run_protocol_routing.py`，可走真实 API 或固定预测。

### 9.4 Prompt A/B

`scripts/prompt_ab_experiment.py` 绕过 Runtime，直接对 `TEST_LLM_*` 调用，隔离提示解释与超时、Pydantic、SQL 校验的影响；记录变体、耗时、token 与结构化结果，用于提示迭代。

### 9.5 评测结论的使用

- 基准通过不等同于企业数据通过；真实企业数据需另行验收。
- 评测结果用于回归与选型参考，不对外宣称“全面领先”。
- 任何提示、工具、模型变更都应重跑题库与路由用例，保留可比性。

## 10 准确性与隐私

### 10.1 准确性

- 事实来自查询：模型只归纳已查询到的数据。
- 断言校验：Claim 必须匹配查询结果；不匹配则重试或部分完成。
- 引用绑定：答案数字附材料编号；无引用的事实不进入结论。
- 缺口显式：字段缺失、查询失败、行数截断都在答案中说明。
- 同期对齐：不使用整月对部分月，避免增长率失真。

### 10.2 隐私

- 只发送最小必要聚合，不发送客户姓名、订单行、完整 CSV。
- 遮蔽字段不进入 Schema 投影、SQL 白名单、模型上下文与报告。
- 日志不记录 Authorization、Key、完整查询结果、模型完整上下文。
- 密钥只存服务端环境变量或加密 Secret；前端只看到 `has_api_key`。
- 演示数据为合成数据，避免使用真实企业信息。

## 11 失败模式与降级

| 失败 | 系统行为 | 用户可见 |
| --- | --- | --- |
| 无 Key | 进入演示模式 / 本地确定性回答 | “演示模式”标签与配置提示 |
| 401 / 402 | 不重试，记录类别 | 明确提示检查 Key / 余额 |
| 超时 / 429 / 5xx | 未输出时有限退避 | “正在重试”或“服务暂时不可用” |
| 输出中断 | 不重放 | “回答中断，请重试或缩小问题” |
| SQL 被拒 | 返回拒绝码，Agent 可修复 | 审计可见，答案说明限制 |
| 沙箱拒绝 | 计入拒绝预算，收尾 | 说明脚本未通过安全策略 |
| DataLink 不可用 | 降级为 Schema 浏览 | 语义增强不可用提示 |
| 证据不足 | 部分完成 | 缺失项与建议 |
| 需要澄清 | 终止并提问 | 澄清问题，不强行猜测 |

## 12 演进方向

1. **指标层**：把“毛利率”“回款率”等口径固化为可复用指标，减少每次重新解释。
2. **更强检索**：DataLink 引入向量召回与术语表，提升业务词命中。
3. **多模型路由**：按任务复杂度在 flash / 更强模型间路由，兼顾成本与质量。
4. **评测扩展**：从 20 题扩到多行业题库，加入人工评分与事实覆盖率。
5. **权限与多租户**：组织、角色、行级权限与数据脱敏策略。
6. **离线私有化**：支持本地模型与私有 DataLink，满足数据不出域。
