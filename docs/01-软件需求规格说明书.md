## 1 文档说明

### 1.1 编写目的

本文档定义智析 ChatBI V1.0 的业务目标、系统范围、用户角色、功能需求、非功能需求、数据与接口约束、安全边界和验收基线。它是需求、设计、实现、测试和验收的唯一入口：设计文档必须能追溯到本文档的需求编号，测试用例必须覆盖 P0 需求，验收记录必须引用用例结果。

### 1.2 系统范围

智析 ChatBI 面向企业经营分析场景，用自然语言完成数据查询、指标分析、图表生成和结论解释。V1.0 包含两条产品路径：

1. **演示路径**：不依赖模型 Key 和企业数据源，使用 906 条合成订单与统一汇总 JSON，保证评审现场可复现。
2. **真实分析路径**：接入 CSV / SQLite / MySQL 只读数据源，经 Schema 检查、字段遮蔽确认、模型激活后，由受控分析 Agent 执行可审计的 Run，产出带证据的答案、图表与 Artifact。

平台内含受控分析运行时、Run 生命周期、工具编排、证据校验、SQL 审计与安全边界，可独立启动、独立测试、独立发布，不依赖外部工作台。

### 1.3 不在范围内

- 不写入企业业务库，不修改源数据，不提供 DDL / DML 能力。
- 不替用户做财务、投资、人事等高风险决策，结论只作为分析参考。
- 不提供企业级多租户、单点登录、细粒度行级权限（V1.0 为单工作空间演示）。
- 不承诺对任意数据源自动建图；DataLink 建图需要模型配置，缺失时降级为 Schema 浏览。
- 演示数据不代表真实企业经营事实，项目台账与收支明细为演示记录。

### 1.4 术语

| 术语 | 定义 |
| --- | --- |
| Session | 一次连续对话会话，聚合多条 Message 与多个 Run |
| Run | 一个用户问题对应的一次独立分析运行，拥有固定上下文、事件流与终态 |
| RunContext | Run 创建时冻结的数据源、Schema 版本、模型配置、DataLink 版本与预算 |
| Agent Runtime | 受控分析状态机，负责阶段推进、工具白名单、预算、熔断与结论提交 |
| DataLink | 业务实体、属性、物理字段、关系与 Join 线索组成的语义地图 |
| Schema | 表、字段、类型、主键、外键、行数等结构信息 |
| 证据链 | SQL 审计、查询结果、Artifact、Claim、引用材料与答案快照的组合 |
| 演示模式 | 无真实数据服务或模型 Key 时，使用固定 CSV 汇总完成展示与问答 |
| Responses API | DeepSeek 提供的 OpenAI SDK Responses 接口，支持流式输出 |
| SSE | Server-Sent Events，服务端向浏览器推送流式片段 |
| Trace DAG | 由 Run 事件推导的执行关系图，展示阶段、工具调用和依赖 |

## 2 产品背景与目标

### 2.1 问题

企业并不缺数据，缺的是把数据变成洞察的通路。传统 BI 存在四个结构性问题：

1. **门槛高**：业务人员需要理解表结构、字段含义、SQL 和图表配置，非技术岗位只能排期等分析师。
2. **链路长**：提出问题、取数、做图、解释口径由不同角色接力，响应以天或周计。
3. **结论不可信**：聊天式工具给出的数字没有来源，无法回答“这个数从哪张表、哪个口径、哪次查询来”。
4. **接入不安全**：直接把企业库交给大模型自由生成 SQL，存在写库、越权、泄露和成本失控风险。

### 2.2 产品定位

**用自然语言打通“人—数据—洞察”的最后一公里。** 平台不是“聊天窗 + 图表”，而是把对话、受控执行、证据和可视化组织成一个可审计的分析工作台。

### 2.3 产品目标

| 编号 | 目标 | 可观察结果 |
| --- | --- | --- |
| G-01 | 降低分析门槛 | 不会 SQL 的用户可用中文完成一次区域营收与回款分析 |
| G-02 | 缩短分析链路 | 从提问到图表与结论在一个页面完成，无需切换工具 |
| G-03 | 结论可信 | 每个数字可回指 SQL 审计 / 查询结果 / Artifact / 引用编号 |
| G-04 | 接入安全 | 模型只能调用白名单工具；SQL 只读；脚本隔离；密钥不出服务端 |
| G-05 | 评审可复现 | 无 Key、无企业数据时仍可完整演示核心能力 |

### 2.4 价值

- **用户价值**：业务、运营、销售、管理者可以“像聊天一样问数据”，减少学习与沟通成本。
- **企业价值**：盘活分散数据资产，缩短“提问—取数—成图—决策”的链路，减少重复取数和报表等待。
- **技术价值**：探索 AI + BI 的轻量化落地形态，把自然语言理解、查询生成、分析编排、可视化推荐组合成闭环。
- **社会与教育价值**：推动数据分析普惠，让非专业用户也具备基本的数据洞察能力。

## 3 用户角色与场景

### 3.1 角色

| 角色 | 目标 | 主要权限 | 关键约束 |
| --- | --- | --- | --- |
| 业务用户 | 低门槛查询经营数据 | 查看驾驶舱、提问、查看报告 | 只能看到已授权数据源与遮蔽后的字段 |
| 数据分析师 | 核对口径与证据 | 管理数据源、Schema、遮蔽、Run、DataLink | 不能绕过只读网关 |
| 模型管理员 | 配置可用模型 | 创建、测试、激活、删除模型配置 | 看不到明文密钥，只能看到配置状态 |
| 项目负责人 | 管理交付质量 | 查看台账、风险、测试与验收 | 演示台账不写外部系统 |
| 评审人员 | 验证作品 | 使用演示模式与操作手册 | 无需 Key 即可完成主流程 |

### 3.2 核心用户旅程

| 步骤 | 用户动作 | 系统行为 | 用户看到 |
| --- | --- | --- | --- |
| 1 | 打开 `/workspace` | 加载汇总数据、健康状态与模块导航 | 指标卡、趋势、渠道、区域、预警、问数框 |
| 2 | 输入“截至 10 月 29 日，各区域营收占比和回款情况如何？” | 校验问题，进入 analyzing | 发送按钮禁用、脉冲状态、来源标签 |
| 3 | 系统分析 | 演示模式走 DeepSeek SSE；真实模式创建 Run 并订阅事件 | 流式文本 / 阶段事件 |
| 4 | 查看结论 | 组织结论、口径、来源、限制与证据入口 | 答案卡、证据按钮、图表联动 |
| 5 | 追问或导出 | 保留会话上下文；报告导出 Markdown | 新回答、报告文件、历史 Run |

### 3.3 典型场景

- **经营例会前 5 分钟**：管理者问“10 月各区域营收和回款怎么样”，得到排名、占比、待回款与毛利变化。
- **运营复盘**：运营问“哪个渠道本月贡献最高、环比如何”，得到渠道构成和趋势。
- **数据治理**：分析师上传新数据源，检查 Schema、确认遮蔽字段，构建 DataLink 语义地图。
- **质量核验**：评审打开 `/analysis`，查看一次 Run 的阶段、SQL、Artifact 与引用材料。

### 4.1 需求总表

| FR-01 | 工作空间与导航 | P0 | 四个路由可访问，模块切换不整页刷新 |
| FR-02 | 演示数据与统一汇总 | P0 | 906 条订单，页面指标与 summary 一致 |
| FR-03 | 数据源接入与 Schema | P0 | CSV / SQLite / MySQL 可接入并显示状态 |
| FR-04 | 字段遮蔽与只读边界 | P0 | 未确认遮蔽不能建 Run；写 SQL 被拒绝并审计 |
| FR-05 | 自然语言问数 | P0 | 中文提问、推荐问题、追问、输入校验 |
| FR-06 | DeepSeek 流式分析 | P0 | SSE 返回 status / delta / error / done |
| FR-07 | 受控 Run 与证据链 | P0 | Run 可创建、订阅、取消、回放，证据可定位 |
| FR-08 | 可视化驾驶舱 | P0 | 指标、趋势、渠道、区域、预警完整 |
| FR-09 | 洞察报告 | P1 | 结论、来源、证据、限制可导出 Markdown |
| FR-10 | 项目流程台账 | P1 | 负责人、阶段、进度、交付可见 |
| FR-11 | 收支管理 | P1 | 收入、成本、回款、明细口径可复算 |

| FR-13 | 演示降级 | P0 | API / Key 不可用时主流程仍可演示 |

### 4.2 FR-01 工作空间与导航

- 默认路由 `/` 重定向到 `/workspace`；另有 `/analysis`、`/datasources`、`/settings/model`。
- 驾驶舱侧栏包含经营驾驶舱、智能问数、洞察报告、项目台账、收支管理；顶部提供刷新、导入、帮助、提醒。
- 导航切换只更新当前视图，不整页刷新；当前项高亮；1280 / 768 / 390 宽度下主操作可访问。
- 所有按钮有 hover、focus-visible 与 pressed 反馈；图表提供 `aria-label`。

**验收**：路由可达；五个模块切换正常；键盘可聚焦；窄屏无页面级横向溢出。

### 4.3 FR-02 演示数据与统一汇总

- 演示 CSV 必须包含订单、区域、城市、客户、产品、客户分层、渠道、时间、金额、成本、毛利、回款状态、销售人员字段。
- 汇总 JSON 由脚本从 CSV 生成，前端不得维护第二套数字；页面指标、图表、报告均读取同一汇总。
- 固定随机种子，订单数 906，日期范围 2026-01-01 至 2026-10-29。

**验收**：订单数 906；累计订单金额 8,079,554.17 元；毛利率 40.06%；待回款 73 笔；10 月截至 29 日 853,824.14 元，较 9 月同期 +1.05%；上述均可由 CSV 重算。

### 4.4 FR-03 数据源接入与 Schema

- 支持 CSV、SQLite 上传与 MySQL 连接；上传限制扩展名、大小（默认 100MB）与受控目录。
- 接入后异步检查 Schema，展示表、字段、类型、行数、主键与关系；状态至少包含 `checking`、`schema_ready`、`ready`、`failed`。
- 未达到 `ready` 的数据源不得创建真实 Run；检查失败可重试，服务重启后能恢复中断检查。

**验收**：三种类型可选择；错误连接有可读提示；Schema 字段与源一致；状态变化可见。

### 4.5 FR-04 字段遮蔽与只读边界

- 敏感字段清单必须由用户显式确认（`mask_fields_confirmed=true`），未确认时创建 Run 返回冲突。
- SQL 经 SQLGlot AST 解析：只允许 `Query`，拒绝 `INSERT / UPDATE / DELETE / CREATE / DROP / INTO` 等写操作。
- 未指定 LIMIT 注入默认 100；指定 LIMIT 必须是整数且不超过 500；单次查询超时 60 秒。
- 每次 SQL 尝试写入审计：原始 SQL、规范化 SQL、状态、拒绝原因、结果行数、耗时、错误码。

**验收**：写 SQL 被拒绝且有审计；未确认遮蔽不能建 Run；结果行数受限；拒绝原因不泄露内部结构。

### 4.6 FR-05 自然语言问数

- 输入 1–2000 字符；Enter 提交，Shift+Enter 换行；空问题、纯空白、超长问题阻止提交。
- 分析期间发送按钮禁用，防重复提交；推荐问题点击后填充并聚焦。
- 同一会话保留上下文；新问题不得覆盖未完成的上一条回答。
- 回答必须标注来源（演示 / 真实 Run / DeepSeek）、时间范围与限制说明。

**验收**：输入规则生效；推荐问题可用；来源标签正确；追问不丢上下文。

### 4.7 FR-06 DeepSeek 流式分析

- 服务端从 `DEEPSEEK_API_KEY` 读取密钥，使用 `AsyncOpenAI` 调用 Responses API，`base_url=https://api.deepseek.com`，`model=deepseek-flash`，`stream=true`。
- 浏览器只访问 `POST /ai/deepseek/analyze`，不直接连接模型服务；请求体只接受 `question`。
- 事件映射：`response.output_text.delta → delta`，`response.completed → done`，失败 → `error`；`status` 表示开始。
- 401（Key 无效）与 402（余额不足）不重试；超时、连接异常、429、5xx 仅在尚未输出文本时有限退避；已输出片段后不重放，避免重复内容。

**验收**：有效 Key 收到 delta 与 done；401/402 不重试；timeout/429 有限重试；错误提示不含 Key 与上游原始响应体。

### 4.8 FR-07 受控 Run 与证据链

- 创建 Run 时冻结 Session、数据源、Schema 版本、模型配置、DataLink 版本、预算与超时。
- Run 事件账本同时服务 SSE 实时订阅与历史回放；事件至少覆盖排队、开始、准备、协议选择、工具调用、产物、答案、成功/失败/取消。
- Agent 仅可调用 `run_sql_readonly`、`run_python`、`explore_datalink`、`commit_analysis_claims` 四个工具。
- 每个问题独立 Run；支持取消；服务重启后恢复未完成 Run 的终态；历史 Run 只读回放，不重复调用模型。
- Artifact 可预览、下载；答案引用可定位到材料编号；Evidence Snapshot 保存答案时的证据状态。

**验收**：Run 状态与事件可查；工具调用有审计；取消生效；重启后可恢复；回放不产生新模型调用。

### 4.9 FR-08 可视化驾驶舱

- 指标卡：10 月截至 29 日订单金额、活跃客户、平均订单金额、累计毛利率。
- 趋势：2026 年 1–10 月月度营收与毛利双折线。
- 构成：当月收入来源环图、区域营收 TOP5 横向柱状图。
- 预警：待回款笔数与金额、当月毛利率及较上月同期变化。
- 所有指标来自统一汇总或真实 Run 产物；tooltip 与说明包含单位、时间范围。

**验收**：图表数据与 summary 对账一致；窗口缩放不裁切；卸载时释放 ECharts 实例与 ResizeObserver。

### 4.10 FR-09 洞察报告

报告包含问题、结论、数据来源、更新时间、证据状态与限制说明；可导出 Markdown；演示与真实来源必须明确区分；真实 Run 报告需附引用编号。

**验收**：导出文件可打开；报告字段完整；来源标签正确。

### 4.11 FR-10 项目流程台账

展示项目名称、负责人、当前阶段、整体进度、预计交付与 AI 进度洞察；V1.0 使用演示记录，不写入企业项目系统。

**验收**：记录可见；演示标签存在；无外部写请求。

### 4.12 FR-11 收支管理

展示净现金流、收入、成本、回款状态、分类与交易明细；金额口径可复算；演示数据不伪装为正式财务凭证。

**验收**：汇总与明细抽样一致；状态标签正确。

### 4.13 FR-12 模型配置安全

- 支持 OpenAI-compatible 服务商、模型名、Base URL、温度、超时、上下文窗口、推理模式。
- API Key 只在提交时传入服务端并加密保存；详情只返回 `has_api_key`，不回显密钥。
- 模型必须通过能力测试（工具调用 / 流式）后才能激活；删除或切换激活模型需保持 Run 快照不变。

**验收**：创建/更新后响应不含密钥；未测试模型不能激活；日志与构建产物搜索不到 Key。

### 4.14 FR-13 演示降级

API 不可用、无模型 Key、无真实数据源或 Schema 未就绪时，系统进入演示模式：保留驾驶舱、指标、图表、问数输入、本地确定性回答与报告导出，并展示“演示”标签。

**验收**：断开 API 后刷新仍可浏览与提问；提示可读；不出现空白页或无限 loading。

## 6 数据与接口需求

### 6.1 前端路由

| 路由 | 页面 | 主要职责 |
| --- | --- | --- |
| `/workspace` | ChatBIDashboard | 驾驶舱、问数、报告、台账、收支 |
| `/analysis` | WorkspaceView | Session / Run 工作台、事件、证据、产物 |
| `/datasources` | DatasourcesView | 数据源、Schema、遮蔽、DataLink |
| `/settings/model` | ModelSettingsView | 模型配置、测试、激活 |

### 6.2 主 API

`GET /health`、`/sessions`、`/datasources`、`/model-profiles`、`/runs/*`、`POST /ai/deepseek/analyze`。成功返回 `{request_id,data,error:null}`，失败返回 `{request_id,data:null,error:{code,message,details}}`。

### 6.3 演示 CSV 字段

`order_id、order_date、region、city、customer_id、customer_name、product、customer_segment、channel、order_time、order_amount、cost_amount、gross_profit、payment_status、sales_rep`。

### 6.4 数据约束

- 金额以人民币元、两位小数保存；页面万元只在格式化层转换。
- 同期比较使用相同截止日：2026-10-01 至 10-29 对比 2026-09-01 至 09-29。
- 缺少漏斗字段时不得计算转化率；缺少成本字段时不得给出毛利率。
- 主键唯一、金额非负、毛利等于金额减成本由数据脚本校验。
