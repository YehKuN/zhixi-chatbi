## 1 录制前准备

1. 运行“启动智析ChatBI.bat”，确认 Web 5280、API 8280、DataLink 8281 健康。
2. 打开 `http://127.0.0.1:5280/workspace`，确认页面显示“演示 · 906 条订单”。
3. 准备一个真实 Run（推荐）：在 `/datasources` 上传 `data/demo/chatbi_sales.csv`，等待 Schema ready，确认遮蔽；在 `/settings/model` 配置并激活 `deepseek-flash`；在 `/analysis` 新建 Session 并提交问题“截至 10 月 29 日，各区域营收占比和回款情况如何？”。
4. 若真实 Run 不可用，使用演示模式的问数与 `/analysis` 的历史 Run 回放作为替代画面，不解说“实时执行”。
5. 录屏软件设置为 1080p、30fps、麦克风降噪；先录 20 秒空镜再开始讲解，方便剪辑。
6. 全程不要切到终端、不要展示 `.env`、不要展示 API Key 或浏览器 localStorage。

## 3 完整解说词

### 0:00–0:15 片头

大家好，我们是「智析 ChatBI」团队。我们的作品是一个 AI 对话式企业数据分析与可视化平台：用一句中文问题，完成取数、分析、成图和解释。

### 0:15–0:45 痛点

传统 BI 的分析链路是“业务提需求、分析师排期、写 SQL、配图表、解释口径”。它门槛高、链路长，结论还经常无法追溯来源。更关键的是，直接把企业数据库交给大模型自由生成 SQL，存在写库、越权、泄露和成本失控的风险。

### 0:45–1:25 驾驶舱

这是智析 ChatBI 的经营驾驶舱。左边是分析空间，中间是核心经营指标：10 月截至 29 日订单金额 85.4 万元、活跃客户 73、平均订单金额和累计毛利率 40.1%。下方是 2026 年 1 到 10 月的营收与毛利趋势，右侧是 AI 智能洞察，底部是收入来源、区域 TOP5 和经营预警。所有数字都来自同一份 906 条订单的汇总，页面不维护第二套数字。

### 1:25–2:40 智能问数

我们在“问问你的数据”里输入：截至 10 月 29 日，各区域营收占比和回款情况如何？点击发送后，页面进入分析状态。配置了 DeepSeek Key 时，回答会通过 SSE 逐片返回；没有 Key 或服务不可用时，系统自动进入演示模式，用本地确定性回答保证评审可复现。

回答不只有一段文字。答案卡会标注数据来源、时间范围和限制；点击“查看证据”，可以看到结论对应的查询、材料和引用编号。我们的原则是：模型负责理解和表达，数字必须来自查询。

### 2:40–3:50 驾驶舱图表与业务模块

趋势图展示月度营收和毛利；环图展示当月收入来源；区域图展示 TOP5；预警区提示 73 笔待回款和毛利率变化。切换到洞察报告，可以看到问题、结论、来源、证据状态和限制，并导出 Markdown。项目台账和收支管理把项目阶段、负责人、进度、收入、成本和回款放在同一个工作台里。它不是问数 Demo，而是企业经营分析的一体化入口。

### 3:50–5:40 受控分析工作台与证据链

现在打开分析工作台。一次问题对应一个 Run；Run 创建时会冻结数据源、Schema、模型和 DataLink 版本。右侧的运行检查台展示阶段、工具调用、SQL 审计和产物；执行关系图把 25 类事件组织成可读的 DAG。

每一次 SQL 都经过 SQLGlot 的只读校验：拒绝写语句、越权表和字段，默认 LIMIT 100，最大 500，单次 60 秒，并记录原始 SQL、拒绝码、行数和耗时。需要复杂计算时，脚本进入 Docker 沙箱：无网络、1 核 CPU、512 兆内存、64 个 PID、只读根文件系统、30 秒超时。模型没有任何直接写库或联网执行代码的能力。

最终答案里的 `[1] [2]` 不是装饰，而是材料编号。模型在答案前必须提交结构化 Claim，运行时会把它和查询结果比对；答案落库时保存 Evidence Snapshot。历史 Run 可以只读回放，不重复调用模型。

### 5:40–6:20 AI 技术亮点

我们的 AI 方案不是自由 ReAct，而是受控 Agent。阶段固定为 Opening、Preparation、Protocol、Discovery、Analysis、Commit、Final Answer；模型只能调用四个白名单工具：只读 SQL、Python 沙箱、DataLink 语义检索、Claim 提交。回合、工具调用、SQL 修复、沙箱拒绝、断言失败都有预算，超出预算就收尾为部分完成或失败，而不是无限重试。

DataLink 是独立的语义服务，通过 MCP 把“回款、区域、客户、订单明细”这样的业务词映射到字段、实体和 Join 路径；每次发布形成不可变版本，Run 创建时冻结版本。

为了证明 AI 质量可回归，我们落地了 20 题中文电商基准、178 条协议路由用例、Prompt A/B 脚本和答案数字审计；后端 772 项、前端 282 项测试通过。

### 6:20–6:50 结尾

智析 ChatBI 想证明的不是“大模型会聊天”，而是“大模型可以在企业数据场景里被安全地使用”。当模型被放进受控运行时，当每个数字都有证据，当没有 Key 也能完整演示，AI 加 BI 才从概念走向可用。让每个决策，都有数据依据。谢谢大家。

## 4 剪辑与字幕

1. 片头、片尾各留 1 秒静帧；场景切换用 0.3 秒淡入淡出，不使用花哨转场。
2. 解说词按分镜时间轴对齐；语速约 230–250 字/分钟，整片控制在 6:20–6:50。
3. 字幕使用 28–34 号微软雅黑，白字 + 半透明黑底，位于画面下方安全区。
4. 关键数字（906、40.1%、772、282、20、178）在字幕中加粗或换色。
5. 导出 MP4：H.264、1920×1080、30fps、AAC 128kbps；文件命名 `智析ChatBI-演示视频-团队名.mp4`。
6. 上传前检查：无 Key、无 `.env`、无终端、无真实客户信息、无其他赛事 Logo。

## 5 备用方案

| 情况 | 处理 |
| --- | --- |
| DeepSeek Key 不可用 | 演示模式问数 + 本地确定性回答；解说“演示模式” |
| 真实 Run 不可用 | 使用历史 Run 回放或工作台已有事件；不解说“实时执行” |
| Docker 不可用 | 只演示 SQL 与 DataLink 路径；解说“Python 产物需 Docker” |
| 网络不稳定 | 全片使用本地演示；提前录制，避免现场直播 |
| 录制中出现弹窗 | 剪辑遮挡或重录；不要展示通知内容 |
