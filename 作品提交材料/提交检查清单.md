## 3 Git 初始化与推送

### 3.1 推荐方案：保留基线历史

如果 DataPilot 原仓库有完整历史，优先在它的历史之上提交本作品改动，这样能体现实质性的开发过程：

```powershell
git clone https://github.com/w402116500/DataPilot.git chatbi-submit
cd chatbi-submit
# 将当前项目文件覆盖到该目录（保留 .git）
# 确认 .env、storage、.venv、node_modules、.tmp 未加入
git status
git add <按模块分批添加>
git commit -m "feat: 智析 ChatBI 企业分析驾驶舱与演示数据"
git commit -m "feat: DeepSeek 流式问数与降级"
git commit -m "feat: 受控 Run 工作台与证据链"
git commit -m "test: 中文电商基准与协议路由评测"
git commit -m "docs: README 与 18 份开发文档"
git remote set-url origin <你的 GitHub/Gitee 仓库地址>
git push -u origin main
```

### 3.2 备选方案：新建仓库

```powershell
cd "智析 ChatBI——AI对话式企业数据分析与可视化平台"
git init
git add .
git commit -m "feat: 智析 ChatBI V1.0 首次提交"
git branch -M main

```

> 单次提交无法体现“真实开发过程”。若只能用备选方案，建议后续按模块补充提交，并在 README 说明版本演进；不要把提交时间伪造成历史时间。
